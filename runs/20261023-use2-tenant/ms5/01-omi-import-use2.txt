lessons (octl/storage mechanics, recorded for the next import):
- octl storage (OOS) does NOT read iaas-style profile credentials by itself:
  OSC_ACCESS_KEY/OSC_SECRET_KEY/OSC_REGION must be exported from the use2
  profile (jq .use2.*) — with only --profile use2 the OOS calls fail with
  "static credentials are empty".
- a single 2 GiB PutObject exceeds a 900 s shell ceiling on this box; multipart
  works: CreateMultipartUpload -> UploadPart (--Body <file>; the streamed
  stdin mode --Body - fails immediately) -> CompleteMultipartUpload. 31 parts
  x 64 MiB took ~42 min wall (~80 s/part).
- CompleteMultipartUpload payload must be built from the SERVER-side ListParts
  (authoritative ETags; the raw output is the usable one — the default output
  prints null): jq '[.Parts[] | {PartNumber, ETag}] | sort_by(.PartNumber)'.
  ETags come back with embedded quotes ("\"abc\"") — do not re-quote them.
- CreateImage with --BlockDeviceMappings.0.* flags hits "too many arguments";
  use --payload JSON with RootDeviceName set (7006 otherwise).
