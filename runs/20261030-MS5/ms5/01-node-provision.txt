== findings (mechanics, for doc 13 §4 next revision) ==
1. ReadVmTypes in us-east-2 lists NO tinav types at all — metal types are
   invisible to the listing API; validity is only knowable from a real
   CreateVms (DryRun does NOT validate VmType — rows 12–15 pass DryRun and
   fail for real).
2. Dedicated-group CpuGeneration must match the VM family generation:
   tinav6 in a gen-7 group → 3002; gen-6 groups accept tinav6.
3. Nested virtualization on gen 6: c8r16p1/c16r32p1/c4r16p1 PASS parameter
   validation (rows 7–10 reached capacity), but tinav6.c4r8p2 + NV → 3002 —
   per-shape, not per-generation. doc 13 §4's "gen-7 node" note stays the
   safe rule; gen-6 c8r16p1 is a proven-valid fallback shape if it ever has
   capacity.
4. nv1/nv2 are not placeable in ANY creatable dedicated group generation
   (4/5/7 tried) — not a metal path for nested virt.
5. octl CreateSecurityGroup rejects non-ASCII in Description (em-dash).
